# v1.0 Pool Support Policy

## Support Tiers

### First-Class Support

- `HikariCP`

For `v1.0.0`, HikariCP is the primary documented, demoed, and regression-validated pool.

That means:

- README examples use HikariCP
- the `demo` module uses HikariCP as the shared default pool
- the main routing and lifecycle regression paths exercise HikariCP directly

### Compatibility Validation

The following pools remain available through the current reflective `DataSource` configuration model, but they are treated as compatibility targets rather than primary baselines:

- `Druid`
- `DBCP2`
- `C3P0`
- `BoneCP`
- `Tomcat JDBC`

For these pools, the project keeps dependency coverage and configuration-model compatibility, but `v1.0.0` does not present them as equal operational defaults.

## Why HikariCP Is The Baseline

- It is the most actively maintained pool in the current dependency set.
- It aligns cleanly with the Java 8 release baseline.
- It is the default pool used by modern Spring Boot baselines the project plans to support next.

## Configuration Rules

MySplitter passes configuration values to the target `DataSource` through bean property setters.

That means pool-specific property names still matter:

- HikariCP expects `jdbcUrl` instead of `url`
- HikariCP uses `connectionTimeout` instead of Druid's `maxWait`
- Other pools continue to use their own setter names

## Example Policy

- Use HikariCP in all new examples, starter smoke paths, and demo configs.
- Keep pool mixing as an advanced compatibility scenario, not the default story.
- When a non-Hikari pool is required, set `dataSourceClass` explicitly and use that pool's setter names in `configuration`.

## Remaining Cleanup To Watch

- There is still no adapter layer that normalizes pool-specific property names across implementations.
- Compatibility pools are still carried in test dependencies, so unmaintained options like BoneCP remain part of the historical surface area.
- A future SPI or adapter abstraction would make the support story cleaner, but that is outside the `v1.0.0` slice.
