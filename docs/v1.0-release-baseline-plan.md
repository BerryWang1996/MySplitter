# v1.0 Release Baseline Plan

## Scope Decision

`v1.0.0` should stay focused on release-baseline work, not observability expansion.

Decision:

- defer failover observability hooks to `v1.1.0`
- keep `v1.0.0` centered on compatibility, packaging, and supported runtime policy

This keeps the release baseline small enough to finish and test confidently.

## Delivery Slices

### Slice 1: Java 8 Baseline

Goal:

- move the minimum supported Java baseline from 7 to 8

Status:

- complete
- Java 8 compiler settings are landed
- Java 6 specific Hikari test dependencies have been removed in favor of standard HikariCP
- downstream starter and demo smoke checks now pass through cold-reactor `clean compile` runs
- upstream modules needed by downstream compile smoke checks now produce jars during `compile`, which avoids the local directory-classpath issue seen in this environment

Tasks:

- update parent Maven compiler settings to Java 8
- remove Java 6 specific test dependencies where standard Java 8 artifacts are now valid
- rerun core, regression, starter, and demo verification commands

Success criteria:

- `mysplitter` builds and tests cleanly on Java 8
- `mysplitter-tests` still covers all supported pool integrations
- downstream starter and demo still compile against the reactor

### Slice 2: Starter Compatibility Cleanup

Goal:

- prepare the starter for a later Spring Boot 2.7 upgrade without mixing that larger change into the Java baseline work

Status:

- in progress
- the downstream reactor-consumption quirk is fixed, so the remaining work is now migration scoping and compatibility documentation

Tasks:

- document current Boot 1.5 / Boot 2.0 split
- isolate starter assumptions that are specific to old Boot auto-configuration
- identify the exact files that will need `spring.factories` and later `AutoConfiguration.imports` handling

Success criteria:

- Boot compatibility work is scoped before implementation starts
- the repo has a clear migration path instead of a monolithic starter rewrite

### Slice 3: Pool Support Policy

Goal:

- make HikariCP the primary supported pool for the release baseline while keeping existing adapters usable during transition

Tasks:

- mark HikariCP as the first-class tested pool in docs and examples
- keep Druid, DBCP2, C3P0, BoneCP, and Tomcat JDBC behind compatibility validation for now
- identify any pool-specific behavior that still needs adapter cleanup before `v1.0.0`

Success criteria:

- the supported pool policy is explicit
- release documentation does not imply equal operational support for every historical pool

## Suggested Order

1. Keep Slice 1 green as the release baseline.
2. Finish Slice 2 scoping before touching the Boot 2.7 implementation.
3. Land Slice 3 documentation and support policy alongside the starter compatibility decisions.
