# v1.0 Starter Compatibility Scope

## Release Baseline

- The parent build and `mysplitter-spring-boot-starter` now align to Spring Boot `2.7.18`.
- The `demo` module now compiles as a Spring Boot `2.7.18` consumer.
- The starter publishes both Boot registration paths needed for the `2.7.x` baseline:
  - `META-INF/spring.factories`
  - `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`

## Current Starter Contract

- Auto-configuration entry point: `com.mysplitter.spring.boot.autoconfigure.MySplitterAutoConfigure`
- Registration mechanisms:
  - `mysplitter-spring-boot-starter/src/main/resources/META-INF/spring.factories`
  - `mysplitter-spring-boot-starter/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
- Configuration properties prefix: `spring.datasource.mysplitter`
- Required external configuration resource: `spring.datasource.mysplitter.configuration-file`
- Produced bean: `com.mysplitter.MySplitterDataSource`

## What Landed In The Boot 2.7 Slice

- `MySplitterAutoConfigure` now uses Boot's `@AutoConfiguration` annotation.
- The starter keeps `spring.factories` for compatibility while also shipping `AutoConfiguration.imports` for the modern Boot discovery path.
- Starter-module tests now verify both metadata files as well as the resource-loading bootstrap behavior.
- The demo consumer moved onto the same Boot generation as the starter baseline.

## Remaining Limits Before Boot 3

- The starter still binds only `spring.datasource.mysplitter.configuration-file` instead of integrating with Boot's standard `DataSourceProperties`.
- The core datasource is still built directly from a MySplitter configuration resource instead of Boot-managed pool builders.
- Boot 3.x will still require a Jakarta-oriented compatibility pass.

## Verification Path

- `.\mvnw.cmd -q -pl mysplitter-spring-boot-starter -am test`
- `.\mvnw.cmd -q -pl mysplitter-spring-boot-starter -am "-Dmaven.test.skip=true" clean compile`
- `.\mvnw.cmd -q -pl demo -am "-Dmaven.test.skip=true" clean compile`
