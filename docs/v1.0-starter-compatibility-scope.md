# v1.0 Starter Compatibility Scope

## Current Split

- The parent build and `mysplitter-spring-boot-starter` still align to Spring Boot `1.5.15.RELEASE`.
- The `demo` module is still a separate Spring Boot `2.0.4.RELEASE` consumer.
- That means the repo currently validates one legacy starter implementation against two different consumer baselines.

## Current Starter Contract

- Auto-configuration entry point: `com.mysplitter.spring.boot.autoconfigure.MySplitterAutoConfigure`
- Registration mechanism: `mysplitter-spring-boot-starter/src/main/resources/META-INF/spring.factories`
- Configuration properties prefix: `spring.datasource.mysplitter`
- Required external configuration resource: `spring.datasource.mysplitter.configuration-file`
- Produced bean: `com.mysplitter.MySplitterDataSource`

## Legacy Assumptions Still In Place

- The starter still relies on Boot 1.x style `spring.factories` registration only.
- There is no `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` file yet.
- The starter binds only its own `configuration-file` property and does not integrate with Boot's standard `DataSourceProperties`.
- The core datasource is still built directly from a MySplitter config resource instead of from Boot-managed pool builders.

## Isolation Work Landed In This Slice

- Resource resolution and MySplitter config parsing are now isolated in `MySplitterConfigurationLoader`.
- `MySplitterAutoConfigure` now uses constructor injection instead of field injection, which makes the bootstrap path easier to test and migrate.
- Starter module tests now lock in classpath loading, file loading, blank-path normalization, and missing-resource failure behavior.

## Files That Will Change For Boot 2.7 / 3.x

- `mysplitter-spring-boot-starter/pom.xml`
- `mysplitter-spring-boot-starter/src/main/java/com/mysplitter/spring/boot/autoconfigure/MySplitterAutoConfigure.java`
- `mysplitter-spring-boot-starter/src/main/java/com/mysplitter/spring/boot/autoconfigure/MySplitterConfigureProperties.java`
- `mysplitter-spring-boot-starter/src/main/java/com/mysplitter/spring/boot/autoconfigure/MySplitterConfigurationLoader.java`
- `mysplitter-spring-boot-starter/src/main/resources/META-INF/spring.factories`
- Future file: `mysplitter-spring-boot-starter/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
- `demo/pom.xml`
- `demo/src/main/resources/application.yml`

## Migration Checkpoints

- Boot 2.7 should add `AutoConfiguration.imports` while keeping `spring.factories` during the overlap window.
- Boot 3.x will require the starter to move from `javax.*` based expectations in consumers toward Jakarta-compatible integration boundaries.
- The demo should be upgraded only after the starter registration path is dual-wired and verified.

## Verification Path

- `.\mvnw.cmd -q -pl mysplitter-spring-boot-starter test`
- `.\mvnw.cmd -q -pl mysplitter-spring-boot-starter -am "-Dmaven.test.skip=true" clean compile`
- `.\mvnw.cmd -q -pl demo -am "-Dmaven.test.skip=true" clean compile`
