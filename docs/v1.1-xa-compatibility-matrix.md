# v1.1 XA Compatibility Matrix

`v1.1.0` ships XA support behind the experimental gate `mysplitter.experimental.xa.enabled=true`; the current decision is to keep it experimental for the `v1.1.0` MVP.

## Current Coverage

| Database | Driver / Module | XADataSource | Coverage | Status |
| --- | --- | --- | --- | --- |
| H2 | `com.h2database:h2:2.1.214` | `org.h2.jdbcx.JdbcDataSource` | Routed two-branch commit, rollback, and non-XA datasource rejection through `MySplitterDataSource`. | Baseline integration coverage. |
| MySQL | `mysql:mysql-connector-java:5.1.46` + `org.testcontainers:mysql:1.20.4` | `com.mysql.jdbc.jdbc2.optional.MysqlXADataSource` | Prepared branch commit and rollback recovery through `FileTransactionLogStore` and `XaRecoveryExecutor`. | Docker-gated recovery coverage. |
| PostgreSQL | `org.postgresql:postgresql:42.2.27` + `org.testcontainers:postgresql:1.20.4` | `org.postgresql.xa.PGXADataSource` | Prepared branch commit and rollback recovery through `FileTransactionLogStore` and `XaRecoveryExecutor`; database-unavailable recovery failure keeps the branch recoverable. | Docker-gated recovery and failure-injection coverage. |

## Required Database Notes

- H2 coverage is used as an always-on routed XA lifecycle baseline; it is not treated as proof of durable crash recovery for production databases.
- MySQL Testcontainers coverage explicitly appends `useSSL=false` because the legacy MySQL 5.1 driver can fail under newer JDKs when SSL negotiation is left implicit.
- PostgreSQL must enable prepared transactions with `max_prepared_transactions > 0`; otherwise `XAResource.prepare(...)` cannot create an in-doubt branch for recovery.
- Every node in `transaction.mode: xa` must configure a valid `xaDataSourceClass` and any required `xaProperties`; MySplitter fails datasource initialization if a selected XA mode node is not XA-capable.

## Verification Commands

Run the always-on H2 XA slice:

```powershell
.\mvnw.cmd -q -pl mysplitter-tests -am "-Dtest=MySplitterH2XaIntegrationTest" "-Dsurefire.failIfNoSpecifiedTests=false" test
```

Run the Docker-backed recovery and failure-injection slices:

```powershell
.\mvnw.cmd -q -pl mysplitter-tests -am "-Dtest=MySplitterMySqlXaRecoveryIntegrationTest,MySplitterPostgreSqlXaRecoveryIntegrationTest,MySplitterPostgreSqlXaRecoveryFailureIntegrationTest" "-Dsurefire.failIfNoSpecifiedTests=false" test
```

Run the full regression module:

```powershell
.\mvnw.cmd -q -pl mysplitter-tests -am test
```

## Still Required Before Release Promotion

- Keep public `transaction.mode: xa` experimental in `v1.1.0` unless a later release-signoff review explicitly changes the support contract.
- Keep `docs/v1.1-xa-operations.md` updated before recommending production use.
