# v1.0 Compatibility Matrix

## Supported Baseline

| Area | Baseline | Notes |
| --- | --- | --- |
| Java runtime | Java 8+ | `v1.0.0` raises the minimum supported baseline from Java 7 to Java 8. |
| Core library | Plain JDBC on Java 8+ | Core routing, failover, and logical-connection regression checks run in `mysplitter` and `mysplitter-tests`. |
| Spring Boot starter | Spring Boot 2.7.x | The starter publishes both `META-INF/spring.factories` and `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`. |
| Demo application | Spring Boot 2.7.18 | The sample app compiles against the same Boot generation as the starter baseline. |
| Demo MyBatis integration | MyBatis Spring Boot Starter 2.3.2 | Kept aligned with the Boot 2.7 demo baseline. |
| First-class pool support | HikariCP | The primary documented and regression-validated pool for `v1.0.0`. |
| Compatibility pool support | Druid, DBCP2, C3P0, BoneCP, Tomcat JDBC | Still supported through the current reflective configuration model, but not the primary operational baseline. |

## Validation Levels

| Validation path | Coverage | Notes |
| --- | --- | --- |
| `.\mvnw.cmd -q -pl mysplitter test` | Core module checks | Keeps `mysplitter` verification from going false-green. |
| `.\mvnw.cmd -q -pl mysplitter-tests -am test` | Cross-module regression suite | Includes always-on H2 routing checks and optional Docker-backed MySQL checks. |
| `.\mvnw.cmd -q -pl mysplitter-spring-boot-starter -am test` | Starter bootstrap and metadata checks | Validates resource loading plus Boot 2.7 dual-registration metadata while building the local core dependency from the same reactor. |
| `.\mvnw.cmd -q -pl demo -am "-Dmaven.test.skip=true" clean compile` | Demo consumer smoke check | Confirms the sample app still compiles against the current reactor. |

## Deferred Work

- Spring Boot 3.x / Jakarta compatibility remains future work.
- Observability and operational metrics remain planned for a later operations-focused milestone.
- Docker-backed MySQL routing validation is kept as a supplemental path on top of the always-on H2 regression baseline.
